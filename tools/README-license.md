# License Unlock Tool — Quick Guide

## Purpose

The POS application is bound to one specific computer. To activate it, you need an unlock code generated for that computer.

The unlock code is different for every computer because it is based on the computer's Machine ID. There is no single code that works on every device.

## Run the tool on the customer's computer

### Option 1: Double-click the batch file

1. Copy `get-license-code.bat` and `get-license-code.ps1` to the customer's computer.
2. Keep both files in the same folder.
3. Double-click `get-license-code.bat`.
4. The window will display the Machine ID and the unlock code.

Example:

```text
==========================================
  Machine ID : e2581e089b3461d6
  Unlock code: 3243
==========================================
```

Send the unlock code to the system administrator or vendor.

### Option 2: Run it manually in PowerShell

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
& ".\tools\get-license-code.ps1"
```

## Activate the application

Enter the generated unlock code in the POS license screen. The user must have the `license.manage` permission.

The code is valid only for the computer whose Machine ID was used to generate it.

## How the script works

The script uses the same algorithms as the backend:

1. It calculates the Machine ID from the computer name, operating system, architecture, and processor information.
2. It calculates the unlock code using HMAC-SHA256 and the private license secret.

This ensures that the code generated by the tool matches the code expected by the backend.

## Calculate a code for a known Machine ID

```powershell
powershell -ExecutionPolicy Bypass -File ".\tools\get-license-code.ps1" -MachineId "abc123..."
```

## License secret

The tool checks these locations in order:

- The `POS_LICENSE_SECRET` environment variable.
- `license.secret` next to the script.
- `license.secret` in the current folder.

The backend checks the `POS_LICENSE_SECRET` environment variable and then `license.secret` next to `pos-server.exe`.

The same secret must be used by both the tool and the backend. If the secrets are different, the generated code will be rejected.

## Secret rotation

To generate a new secret:

```powershell
powershell -ExecutionPolicy Bypass -File ".\tools\generate-license-secret.ps1" -Path "license.secret"
```

Keep the new secret next to `pos-server.exe` and use the same secret when generating unlock codes.

Never commit `license.secret` or share it with the customer. It is a private vendor secret.

## Seed demo data

For screenshots and demonstrations, start the local POS server and run:

```powershell
powershell -ExecutionPolicy Bypass -File ".\tools\seed-demo-data.ps1"
```

The script logs in with `admin` / `1234`, creates a complete demo dataset,
and stops without changes when demo products already exist. It creates master
data, products, multiple units, a service, a bundle, a supplier, a client, an
employee, a posted purchase, an open shift, cash and credit invoices, payments,
and a cash expense. Demo records are named with the `DEMO -` prefix so they can
be recognized easily. Do not run it against a customer's production database.
